## 1. Storage Contract Amendment

- [ ] 1.1 Amend the accepted storage statement — Carry the MODIFIED `platform-runtime-operations` delta in this change: "Independent platform runtime" drops the 250 GB attached-volume mandate and states that all storage local to the host is replaceable, that no requirement depends on a specific device, mount point, or capacity, and that attached Block Storage is optional capacity or performance expansion whose absence blocks nothing; "S3 durable recovery boundary" is reworded from "the VPS and attached volume" to "the VPS and every storage device local to it" so it no longer presumes a volume exists. Do not weaken the recovery obligation in either. Do not modify "PostgreSQL point-in-time recovery", "Provider-backup removal gate", "Bitwarden secret recovery", or "Backup and recovery observability". Keep every provider-specific schedule, retention count, bucket name, role name, and ARN out of the capability text.
- [ ] 1.2 Record the amendment as a decision — Add `docs/decisions/0010-replaceable-local-storage-and-s3-backup-repository.md` stating the final storage boundary, the separate backup identity, and the keyless credential posture, with rejected alternatives and consequences. Update ADR-0001 and ADR-0002 status lines to record that ADR-0010 amends their storage statements, leaving the original July text intact as the record of what was decided then. Add ADR-0010 to the `docs/decisions/README.md` table.

## 2. AWS Backup Repository and Identity

- [ ] 2.1 Create the backup S3 repository and identity — Using administrative credentials, which the runtime host deliberately does not hold: create bucket `trupryce-property-tax-backups` with public access blocked, default SSE, versioning, and a lifecycle rule bounding noncurrent-version retention; create IAM role `trupryce-data-platform-backup` whose permission policy allows object read, write, list, and delete confined to `arn:aws:s3:::trupryce-property-tax-backups/pgbackrest/platform/*` plus the `ListBucket` needed for that prefix, and nothing else; set its trust policy to allow `sts:AssumeRole` from the existing Roles Anywhere trust anchor only, with a condition restricting `aws:PrincipalTag/x509Subject/CN` to `trupryce-data-platform-vps`; create a Roles Anywhere profile bound to that role alone. Do not modify `trupryce-data-platform-vps`, do not grant it delete anywhere, and do not grant the backup role any authority over the source-data location. Create no access key.
- [ ] 2.2 Prove the backup identity in isolation — From the runtime host, exchange the existing workload certificate through the new profile and assert `sts:GetCallerIdentity` resolves to `assumed-role/trupryce-data-platform-backup`. Assert the backup identity can list the backup bucket and cannot reach the data location, and that the data role still cannot reach the backup prefix. Record the assertions and the resolved ARNs; record no credential material.

## 3. PostgreSQL Image and Archive Configuration

- [ ] 3.1 Install pinned pgBackRest and the signing helper into the PostgreSQL image — In `infra/postgres/Dockerfile`, install `pgbackrest=2.59.1-1.pgdg12+1` from the PGDG repository the official `postgres:16.11-bookworm` image already configures, pinning the exact package version so an upstream bump cannot arrive silently, and fail the build if the resolved version is not 2.59.1. Do not use Debian Bookworm's stock 2.45, which has no `process` S3 key type. Copy `aws_signing_helper` 1.8.4 into the image from a pinned, checksum-verified release artifact. Create the pgBackRest log, spool, and configuration directories owned by the `postgres` user. Bake no certificate, private key, passphrase, ARN, or credential into any layer.
- [ ] 3.2 Add the credential-process wrapper — Add `infra/postgres/pgbackrest/aws-credential-process.sh`, installed into the image as `/usr/local/bin/pgbackrest-aws-credentials`. It takes the trust anchor, profile, and role ARNs and the certificate paths from environment variables set by Compose, validates that each is present, and `exec`s `aws_signing_helper credential-process` so the helper's exit status is the wrapper's. It MUST pass the helper's stdout through unmodified — no parsing, reformatting, caching, or logging — and MUST NOT write credential material to disk or echo it. Add a `set -euo pipefail` guard and quote every expansion.
- [ ] 3.3 Add the pgBackRest configuration — Add `infra/postgres/pgbackrest/pgbackrest.conf` declaring stanza `platform`, `repo1-type=s3`, bucket `trupryce-property-tax-backups`, `repo1-path=/pgbackrest/platform`, region and endpoint, `repo1-s3-key-type=process` with the wrapper as `repo1-s3-key-process`, `repo1-retention-full=4` with `repo1-retention-full-type=count`, `repo1-cipher-type=aes-256-cbc`, `compress-type=zst`, `archive-async=y` with a spool path, and `start-fast=y`. The file carries no passphrase, no ARN secret, and no credential: the cipher passphrase arrives as `PGBACKREST_REPO1_CIPHER_PASS` from Bitwarden. Confirm the file is safe to commit by asserting it in the contract tests.
- [ ] 3.4 Wire archiving into the PostgreSQL service — In `infra/compose.yaml`, run PostgreSQL with `archive_mode=on`, `archive_command='pgbackrest --stanza=platform archive-push %p'`, `archive_timeout=300`, and a `wal_level` sufficient for physical backup. Bind-mount `/etc/trupryce/aws` read-only. Pass `PGBACKREST_REPO1_CIPHER_PASS` from the Bitwarden-resolved `PGBACKREST_CIPHER_PASS`, and pass the three ARNs and two certificate paths as ordinary non-secret configuration from `infra/.env`. Add named volumes for the pgBackRest log and spool directories. Do not pass `BWS_ACCESS_TOKEN` into any container. Keep every administrative port on loopback or the approved Tailscale range.
- [ ] 3.5 Add the cipher passphrase to Bitwarden — Generate a high-entropy `PGBACKREST_CIPHER_PASS` and store it in the existing `tax-platform` project with a write-capable machine account, never the read-only runtime account. Add it to the documented secret inventory in `infra/README.md` and to `generate-runtime-secrets.sh` so a clean-host rebuild creates it. Record that losing this value makes every existing backup unrecoverable.

## 4. Host Scheduling

- [ ] 4.1 Add the backup wrapper script — Add `infra/scripts/pgbackrest-backup.sh` taking a backup type (`full` or `diff`). It locates the PostgreSQL container by Compose labels `com.docker.compose.project=property-tax-platform` and `com.docker.compose.service=postgres` rather than by a generated container ID or name, fails closed with a distinct status when zero or more than one container matches, and `docker exec`s pgBackRest as the `postgres` user. It prints no credential and no configuration value.
- [ ] 4.2 Add systemd units and timers — Add `infra/systemd/pgbackrest-full.service`/`.timer` and `pgbackrest-diff.service`/`.timer` under the repository, with the full timer weekly and the differential timer daily, `Persistent=true` so a missed run after downtime still fires, and a `RandomizedDelaySec` so the two do not collide. Units call the wrapper from task 4.1, run as the Docker-capable service account, and do not depend on Airflow in any way. Document installation, because installing into `/etc/systemd/system` needs root the automation does not hold.

## 5. Operational Proof

- [ ] 5.1 Prove the repository end to end on the Akamai host — In order, recording actual command output: the backup STS identity resolves to `assumed-role/trupryce-data-platform-backup`; the backup bucket lists; `pgbackrest --stanza=platform stanza-create` succeeds; `pgbackrest --stanza=platform check` succeeds; a forced WAL segment appears as an S3 object under `pgbackrest/platform/archive`; a full backup completes and appears under `pgbackrest/platform/backup`; and `pgbackrest --stanza=platform info` reports it. Record no credential and no production source data.
- [ ] 5.2 Prove point-in-time recovery in isolation — Create a disposable recovery marker table. Commit a `before` state, force WAL archival, wait past the boundary, commit an `after` state, force WAL archival again, and choose a target timestamp strictly between them. Restore into a **new temporary Docker volume** — never `postgres-data` — and start an isolated PostgreSQL container on a loopback-only non-production port. Assert the restored cluster proves all six: `property_tax` exists, `airflow` exists, the four runtime roles exist, marker `before` is present, marker `after` is absent, and the cluster starts cleanly with recovery complete. Tear down the temporary volume and container afterwards.
- [ ] 5.3 Record the recovery evidence — Record measured RPO, measured RTO, the backup label restored from, the target timestamp, and each validation result, in the runbook. Record no credential, no certificate material, no passphrase, and no production source data. State plainly which parts were exercised and which were not.
