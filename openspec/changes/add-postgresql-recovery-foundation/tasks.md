## 1. Storage Contract Amendment

- [x] 1.1 Amend the accepted storage statement — Carry the MODIFIED `platform-runtime-operations` delta in this change: "Independent platform runtime" drops the 250 GB attached-volume mandate and states that all storage local to the host is replaceable, that no requirement depends on a specific device, mount point, or capacity, and that attached Block Storage is optional capacity or performance expansion whose absence blocks nothing; "S3 durable recovery boundary" is reworded from "the VPS and attached volume" to "the VPS and every storage device local to it" so it no longer presumes a volume exists. Do not weaken the recovery obligation in either. Do not modify "PostgreSQL point-in-time recovery", "Provider-backup removal gate", "Bitwarden secret recovery", or "Backup and recovery observability". Keep every provider-specific schedule, retention count, bucket name, role name, and ARN out of the capability text.
- [x] 1.2 Record the amendment as a decision — Add `docs/decisions/0010-replaceable-local-storage-and-s3-backup-repository.md` stating the final storage boundary, the separate backup identity, and the keyless credential posture, with rejected alternatives and consequences. Update ADR-0001 and ADR-0002 status lines to record that ADR-0010 amends their storage statements, leaving the original July text intact as the record of what was decided then. Add ADR-0010 to the `docs/decisions/README.md` table.

Record the assertions and the resolved ARNs; record no credential material.

## 3. PostgreSQL Image and Archive Configuration

- [x] 3.1 Install pinned pgBackRest and the signing helper into the PostgreSQL image — In `infra/postgres/Dockerfile`, install `pgbackrest=2.59.1-1.pgdg12+1` from the PGDG repository the official `postgres:16.11-bookworm` image already configures, pinning the exact package version so an upstream bump cannot arrive silently, and fail the build if the resolved version is not 2.59.1. Do not use Debian Bookworm's stock 2.45, which has no `process` S3 key type. Copy `aws_signing_helper` 1.8.4 into the image from a pinned, checksum-verified release artifact. Create the pgBackRest log, spool, and configuration directories owned by the `postgres` user. Bake no certificate, private key, passphrase, ARN, or credential into any layer.
- [x] 3.2 Add the credential-process wrapper — Add `infra/postgres/pgbackrest/aws-signing-process.sh`, installed into the image as `/usr/local/bin/pgbackrest-aws-signing`. Neither path contains the word `credential`, because the review-packet guard treats any such path as credential material and refuses to emit the diff; renaming keeps that guard at full strength rather than adding an exemption a later file could hide behind. It takes the trust anchor, profile, and role ARNs and the certificate paths from environment variables set by Compose, validates that each is present, and `exec`s `aws_signing_helper credential-process` so the helper's exit status is the wrapper's. It MUST pass the helper's stdout through unmodified — no parsing, reformatting, caching, or logging — and MUST NOT write credential material to disk or echo it. Add a `set -euo pipefail` guard and quote every expansion.
- [x] 3.3 Add the pgBackRest configuration — Add `infra/postgres/pgbackrest/pgbackrest.conf` declaring stanza `platform`, `repo1-type=s3`, bucket `trupryce-property-tax-backups`, `repo1-path=/pgbackrest/platform`, region and endpoint, `repo1-s3-key-type=process` with the wrapper as `repo1-s3-process-cmd`, which is the option pgBackRest 2.59.1 defines — `repo1-s3-key-process` is not an alias and is silently dropped with a warning, `repo1-retention-full=4` with `repo1-retention-full-type=count`, `repo1-cipher-type=aes-256-cbc`, `compress-type=zst`, `archive-async=y` with a spool path, and `start-fast=y`. The file carries no passphrase, no ARN secret, and no credential: the cipher passphrase arrives as `PGBACKREST_REPO1_CIPHER_PASS` from Bitwarden. Confirm the file is safe to commit by asserting it in the contract tests.
- [x] 3.4 Wire archiving into the PostgreSQL service — In `infra/compose.yaml`, run PostgreSQL with `archive_mode=on`, `archive_command='pgbackrest --stanza=platform archive-push %p'`, `archive_timeout=300`, and a `wal_level` sufficient for physical backup. Bind-mount `/etc/trupryce/aws` read-only. Pass `PGBACKREST_REPO1_CIPHER_PASS` from the Bitwarden-resolved `PGBACKREST_CIPHER_PASS`, and pass the three ARNs and two certificate paths as ordinary non-secret configuration from `infra/.env`. Add named volumes for the pgBackRest log and spool directories. Do not pass `BWS_ACCESS_TOKEN` into any container. Keep every administrative port on loopback or the approved Tailscale range.
- [x] 3.5 Add the cipher passphrase to Bitwarden — Generate a high-entropy `PGBACKREST_CIPHER_PASS` and store it in the existing `tax-platform` project with a write-capable machine account, never the read-only runtime account. Add it to the documented secret inventory in `infra/README.md` and to `generate-runtime-secrets.sh` so a clean-host rebuild creates it. Record that losing this value makes every existing backup unrecoverable.

## 4b. Review Corrections

- [x] 4b.1 Use the option pgBackRest actually defines — `repo1-s3-process-cmd`, not `repo1-s3-key-process`. pgBackRest treats an unknown option in a configuration *file* as a warning and continues, so the wrong spelling parsed cleanly, was dropped, and left the repository unable to authenticate while every string-matching test passed. Correct the configuration, the OpenSpec wording, the design diagram, and the tests together.
- [x] 4b.2 Add a built-image configuration parse gate — Execute the pinned pgBackRest binary from the built image against the committed configuration in a mode that parses configuration without reaching PostgreSQL or S3, and fail the gate on any `invalid option` or `invalid value` warning and on a missing resolved `--repo1-s3-process-cmd`. Assert on the warning text and the resolved option set rather than on exit status, which is zero either way. Prove by mutation that the previously undetected misspelling now fails.
- [x] 4b.3 Establish a readable, least-privilege certificate contract — A read-only mount proves immutability, not readability: the container's postgres user is uid 999 and the host key is owned by the operator, so `archive_command` would fail at runtime. Own the certificate directory and key by a dedicated GID, keep the key `0640` and never world-readable, never `0644`, never unrestricted, and never copied into an image, and join the PostgreSQL service to that GID as a supplementary group. Prove from the built container that postgres can read the key, that a container without the group cannot, and that the mount is still not writable. Add deterministic tests for the UID/GID/mode/mount contract.
- [x] 4b.4 Add a restore wrapper on the approved secret boundary — Resolve the cipher passphrase from Bitwarden inside the wrapper and pass it to Docker by reference as `-e NAME`, never as `-e NAME=value`, so it never reaches argv, shell history, or a process listing. Keep the Bitwarden access token host-only and out of Compose and containers. Give the recovered cluster the same pinned image, an isolated temporary volume, the read-only certificate mount and group, the backup ARNs, and a loopback-only non-production port, because reaching the target runs `archive-get` during startup and needs working credentials. Refuse the production volume by name and any Compose-managed volume by label.
- [x] 4b.5 Make the systemd units portable — Replace hard-coded operator account and home path with templates plus a deterministic install script that resolves the service user, repository path, and Docker group at install time, creates the certificate group at the configured GID, refuses to continue on an unsubstituted placeholder, and checks rather than grants Docker access. Preserve host scheduling, no Airflow dependency, Compose-label container selection, `Persistent=true`, full/differential mutual exclusion, and least privilege.
- [x] 4b.6 Correct the runtime-secret count accounting — Derive every reported count from the arrays that produce the secrets rather than restating a literal, so adding the next secret cannot reintroduce the drift, and test the reported count against the file actually written without exposing a value.
- [x] 4b.7 Repair the AWS runbook to match the procedure that worked — Use `aws --profile boss` for every administrator command and keep workload verification on `trupryce-data-vps` and `trupryce-backup`. Record the failures actually encountered: `us-east-1` must omit `--create-bucket-configuration`; the backup role ARN must be retrieved and validated rather than read from a stale shell variable; the Roles Anywhere profile must be created with `--enabled` and its ARN retrieved and validated afterwards. Document the VPS-local `trupryce-backup` profile using `credential_process`, name the existing data profile `trupryce-data-vps` correctly, and verify both directions of the isolation. Retain bucket hardening and record that it is verifiable only with administrator credentials.
- [x] 4b.8 Add an actionable certificate expiry check — Report the not-after date and days remaining and exit non-zero inside the warning window, without claiming that renewal automation or alerting exists.
