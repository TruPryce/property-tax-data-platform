## 2. The Atomic Processor

<!-- countyforge-task: 2.1 paths=libs/property-tax-adapters/src/property_tax_adapters/release/processor.py checks=repo.check risk=higher_risk prerequisites=D1,D2,D3,D5,D8,D10,D11,D13,1.2,1.3 -->
- [ ] 2.1 Add `process_release`, the fixed order, and the failure mapping — Add `processor.py` with `process_release` as a function over a caller-supplied reader and stage, holding neither beyond the call. Implement exactly this order: prepare the reader and validate its layout, capturing `PreparedRelease`; only then open the stage; call the resource guard once before the first write; for each row envelope write its records to the invisible stage; at every 100,000-physical-row boundary call the guard and emit a non-final progress event; at end-of-input call the guard once and emit exactly one final progress event; then finalize; then commit exactly once. The final progress event SHALL precede finalize and commit, so a raising final callback can still reject while zero records are visible. A layout failure SHALL NOT open a stage and SHALL NOT call `abort`; abort runs if and only if the stage was entered. Implement the exhaustive failure-to-code mapping: preparation or layout validation to `layout_rejected`, reader iteration or row validation to `record_rejected`, `DuplicateRecordKey` from `write` to `duplicate_record_key`, any other `write` exception to `stage_write_failed`, `finalize` to `stage_finalize_failed`, `commit` to `stage_commit_failed`, any callback exception to `progress_callback_failed`, and any guard exception to `resource_limit_exceeded`; no phase borrows another's code and no decision inspects exception text. Discard every exception message. Count physical rows from envelopes and staged records from the records within them, never deriving one from the other. Retain no key set, retain no row after writing it, and hold no reference to the member after returning.
