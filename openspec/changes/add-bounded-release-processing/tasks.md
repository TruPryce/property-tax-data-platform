the protocol fixes what is passed and never what is measured. Neither context manager's `__exit__` may suppress an exception, since a suppressed failure is one the processor cannot map to a code. Every signature in the capability spec's table is declared exactly, so two independent implementations are interchangeable rather than merely similarly shaped. Implement exactly this order: enter the reader; prepare and validate its layout capturing `PreparedRelease`; enter the stage; call the guard once before the first write; per envelope verify record agreement and write its records, calling the guard and emitting a non-final progress event at every 100,000-physical-row boundary; at end-of-input call the guard once and emit exactly one final progress event; exit the reader; finalize; commit exactly once; exit the stage. A layout failure SHALL NOT enter a stage and SHALL NOT call `abort`; abort runs if and only if the stage was entered, and an abort that itself fails records `stage_abort_failed` without changing a disposition that is already rejected. Discard every exception message. Count physical rows from envelopes and staged records from the records within them, never deriving one from the other, and report `committed_record_count` as zero unless the commit succeeded. Retain no key set, retain no row after writing it, and hold no reference to the member after returning.
