## 2. The Atomic Processor

<!-- countyforge-task: 2.1 paths=libs/property-tax-adapters/src/property_tax_adapters/release/processor.py checks=repo.check risk=higher_risk prerequisites=D1,D2,D3,D5,D8,D10,D11,1.1,1.2 -->
- [ ] 2.1 Add `process_release` and the D2 order — Add `processor.py` with `process_release` as a function over a caller-supplied reader and stage, holding neither beyond the call. Implement the exact order: prepare the reader and validate its layout capturing the fingerprint; only then open the stage; per physical row decode, validate, and write to the invisible stage; finalize release-wide checks after end-of-input; commit exactly once after every blocking check succeeds. A layout failure SHALL occur before the first stage write and SHALL NOT open a stage. Any reader, parser, row-validation, duplicate, resource-limit, progress-callback, stage-write, finalize, or commit failure aborts the stage and returns a rejected outcome carrying zero accepted records, never staged records. Emit a non-final `ReleaseProgressEvent` after every 100,000 physical rows and exactly one final event at end-of-input, including for an exact multiple and for an empty release, with sequence numbers that are deterministic and gapless. A raising callback rejects with `progress_callback_failed` and its exception text is discarded rather than recorded. Accept a caller-supplied bound whose breach reports `resource_limit_exceeded`, so the code is reachable before change two supplies a measured limit. Retain no key set, retain no row after writing it, and hold no reference to the member after returning.
