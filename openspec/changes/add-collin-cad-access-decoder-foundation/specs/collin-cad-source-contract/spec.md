## ADDED Requirements

### Requirement: Decode the observed NUMERIC wrapper exactly

The Collin adapter SHALL decode only the approved 17-byte NUMERIC wrapper by interpreting the canonical sign byte and four little-endian 32-bit magnitude words in most-significant-word-first order, and it MUST construct the result directly as an exact Decimal using approved external precision and scale metadata without binary floating-point conversion, rounding, or exponent coercion.

#### Scenario: Decode an independent signed multiword vector
- **GIVEN** an independently authored 17-byte negative multiword NUMERIC literal
- **GIVEN** approved precision and scale metadata
- **GIVEN** a reviewed exact negative Decimal expectation
- **WHEN** the Collin NUMERIC decoder decodes the literal result for comparison with the reviewed expectation and representation constraints.
- **THEN** the reviewed exact negative Decimal is returned
- **THEN** the sign, scale, precision, byte order, and word order are preserved
- **THEN** no float conversion, rounding, or exponent coercion occurs

### Requirement: Keep NUMERIC fixtures independent and synthetic

The adapter test corpus MUST contain reviewed literal vectors for canonical zero, positive, negative, scaled, multiword, precision-boundary, 2025, 2026, and monetary values, and fixture expectations MUST NOT be generated by an encoder or helper that mirrors the decoder under test.

#### Scenario: Review fixture independence
- **GIVEN** the committed Collin NUMERIC fixture manifest
- **GIVEN** the fixture source containing reviewed byte literals and Decimal expectations
- **WHEN** a maintainer inspects how the expected vectors are defined and traces their documented synthetic provenance.
- **THEN** each required vector class is represented by an explicit literal
- **THEN** the expected Decimal values are recorded independently
- **THEN** no production decoder, mirrored encoder, county row, or Access database generates the vectors

### Requirement: Validate the bounded AD_Public structure

The Collin adapter SHALL validate the exact AD_Public table and required privacy-minimized column descriptors by exact case-sensitive name and compatible type, width, precision, scale, and nullability; it MUST reject missing, unexpected, duplicate, colliding, renamed, aliased, positional, or incompatible required structure before row conversion.

#### Scenario: Reject an incompatible required column
- **GIVEN** synthetic AD_Public schema metadata containing all other required columns
- **GIVEN** curr_val_yr declared with a nonzero scale
- **GIVEN** a deterministic schema fingerprint computed from all observed descriptors
- **WHEN** the Collin schema validator evaluates the supplied metadata before any row conversion begins.
- **THEN** schema validation fails before any row is converted
- **THEN** the incompatible_scale diagnostic is produced
- **THEN** the schema is classified as unsupported
- **THEN** no positional or alias-based fallback is attempted

### Requirement: Treat schema fingerprints as provenance

The Collin adapter SHALL compute the schema fingerprint as SHA-256 over canonical UTF-8 JSON containing the parser contract version, exact table name, and every observed column descriptor sorted by exact column name; the fingerprint MUST remain provenance rather than an allowlist, and additional metadata columns MUST NOT have their row values read or retained.

#### Scenario: Accept metadata-only extra columns
- **GIVEN** compatible descriptors for every required AD_Public column
- **GIVEN** one additional non-required metadata column
- **GIVEN** a synthetic row whose extra-column value is not supplied to the bounded projection
- **WHEN** the adapter validates the observed schema and constructs its bounded row projection.
- **THEN** required-column compatibility succeeds
- **THEN** extra_columns_present is reported as a non-fatal schema diagnostic
- **THEN** the additional descriptor changes the observed fingerprint
- **THEN** the additional column value is neither read nor retained

### Requirement: Preserve source grain without approving identity

The Collin adapter SHALL parse approved synthetic rows into typed adapter-local records, MUST preserve valid prop_id and geo_id values and repeated physical rows, and MUST reject invalid identifiers, statuses, years, monetary values, and inconsistent null families without approving prop_id or geo_id as a unique account key or performing deduplication or account roll-up.

#### Scenario: Preserve repeated physical source rows
- **GIVEN** two valid synthetic rows with the same prop_id and geo_id
- **GIVEN** different one-based physical row numbers
- **GIVEN** valid status, year, and value-family fields
- **WHEN** the Collin row parser converts both rows within one logical input.
- **THEN** two typed source records are retained
- **THEN** each record preserves its source prop_id, geo_id, and physical row number
- **THEN** the records are not deduplicated or rolled up
- **THEN** neither identifier is represented as an approved canonical account key

### Requirement: Keep current and certified observations separate

The Collin adapter SHALL emit one current observation from curr_val_yr, property_status, and curr_* fields and, when the certified family is consistently populated, a separate certified observation from cert_val_yr and cert_* fields; the two immutable observations MUST NOT overwrite, merge, suppress, or fill values for one another even when their years or values match.

#### Scenario: Emit current and certified observations from one row
- **GIVEN** a valid synthetic Collin source row
- **GIVEN** curr_val_yr equal to 2026 with current values and property_status Preliminary
- **GIVEN** cert_val_yr equal to 2025 with populated certified values
- **GIVEN** caller-supplied release and source-member identifiers
- **WHEN** the adapter normalizes the typed source record into adapter-local logical observations.
- **THEN** one current observation classified as preliminary is emitted for 2026
- **THEN** one distinct certified observation is emitted for 2025
- **THEN** each observation retains its family, year, status, source columns, release, member, table, physical row, contract version, and schema fingerprint
- **THEN** no value is copied between the current and certified families

### Requirement: Fail closed with privacy-safe diagnostics

The Collin adapter MUST reject malformed non-null NUMERIC buffers, unsupported signs or metadata, precision overflow, negative zero, invalid identifiers, invalid property status, invalid years, invalid appraisal monetary values, and inconsistent certified families with stable diagnostic codes, and diagnostics MUST NOT contain complete rows, arbitrary source values, owner or DBA names, mailing or situs addresses, protected identities, credentials, or host-local paths.

#### Scenario: Reject a malformed value without leaking row content
- **GIVEN** a synthetic row with an invalid non-null monetary NUMERIC buffer
- **GIVEN** a one-based row number
- **GIVEN** a validated schema fingerprint
- **WHEN** the adapter attempts to parse the malformed monetary field during logical row conversion.
- **THEN** the logical conversion fails deterministically
- **THEN** the value does not become None or a float
- **THEN** the diagnostic contains only its stable code, field or table name, row number, and schema fingerprint
- **THEN** the diagnostic contains no complete row or arbitrary source value

### Requirement: Keep the foundation adapter-local and non-production

The implementation MUST remain within the Collin property_tax_adapters source module, adapter-local tests and synthetic fixtures, and directly related source documentation; it SHALL NOT add network access, county artifacts, an Access runtime or container dependency, production acquisition, persistence, migrations, Bronze or Gold behavior, services, DAGs, domain or application types, owner publication, deployment behavior, or a production-ready designation.

#### Scenario: Exercise the foundation without a production runtime
- **GIVEN** the independently authored Collin synthetic fixtures
- **GIVEN** the adapter-local decoder, schema validator, records, and normalizer
- **GIVEN** an environment with no county archive, Access database, network access, or Access runtime
- **WHEN** the Collin adapter contract tests execute against the synthetic fixture corpus.
- **THEN** the approved decoding, validation, and dual-observation behavior is exercised
- **THEN** no official county system or file host is contacted
- **THEN** no owner or mailing data is processed
- **THEN** the test result does not designate the adapter as production-ready
