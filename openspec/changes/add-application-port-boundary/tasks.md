# Tasks

Every module below lives in `libs/property-tax-application/src/property_tax_application/`. Where a
task says a type is **frozen**, it means a frozen slotted dataclass validating in `__post_init__` and
raising `ValueError`, matching the established style of `AcquiredArtifact` and the canonical record
model. Where it says a port is a **Protocol**, it means `@runtime_checkable class X(Protocol)`,
matching `ArtifactSink` and `BronzeStore`.

No task adds a dependency to `property-tax-application`. No task edits a migration, an adapter, or a
county module.

## 1. The shared run vocabulary

<!-- countyforge-task: 1.1 paths=libs/property-tax-application/src/property_tax_application/runs.py checks=repo.check risk=higher_risk prerequisites=D1,D10 -->
- [ ] 1.1 Add the processing-run vocabulary — Add `runs.py` carrying `ProcessingRunRef`, a frozen type wrapping one persistence-generated value, whose docstring states in its first line that it is an **opaque locator**: comparable for equality, carrying no ordering, freshness, or precedence meaning, and never canonical identity. Give it equality and hashing and deliberately no ordering methods, so a caller cannot sort by it without writing a key function that makes the intent obvious. Add `ReleaseProcessingOutcome`, a frozen type carrying `disposition` (a `ReleaseDisposition` StrEnum of exactly `accepted` and `rejected`), `physical_rows_processed`, `staged_record_count`, `committed_record_count`, `rejected_row_count`, `total_diagnostic_count`, `diagnostics_truncated`, `total_notice_count`, `notices_truncated`, and bounded `diagnostics` and `notices` tuples. Mirror the invariants the accepted database model already enforces so a violation is caught at the boundary rather than at COMMIT: accepted exactly when the diagnostic count is zero, accepted commits what it staged, accepted rejected no row, rejected commits nothing, committed never exceeds staged, and no count negative. State in the module docstring that this is the application's own outcome value and that the adapters' `ReleaseOutcome` maps onto it, because the dependency direction forbids the reverse.

## 2. Source registry and discovery

<!-- countyforge-task: 2.1 paths=libs/property-tax-application/src/property_tax_application/sources.py checks=repo.check risk=normal prerequisites=D1 -->
- [ ] 2.1 Add the source registry port — Extend `sources.py` with `UnsupportedSource`, an exception naming the requested jurisdiction and release kind, and `SourceRegistry`, a Protocol with one method resolving a jurisdiction and release kind to a `CountySourceDefinition` and raising `UnsupportedSource` otherwise. Document that resolution performs no network access, because the accepted requirement is that an unregistered source fails *before* acquisition. Do not change `CountySourceDefinition` or `AcquisitionMethod`. Do not move the existing adapters registry; this task defines the contract it will satisfy.

Add `ReleaseDiscovery`, a Protocol returning candidates for a resolved source definition. Assert in the type's validation that it carries no credential-shaped field and no unbounded payload. Do not perform or model county parsing here.

## 3. Canonical persistence

<!-- countyforge-task: 3.1 paths=libs/property-tax-application/src/property_tax_application/canonical.py checks=repo.check risk=higher_risk prerequisites=D2,D3,D4,D5,D6,1.1 -->
- [ ] 3.1 Add the canonical batch and completion values — Add `canonical.py` carrying `CanonicalRecordBatch`, a frozen type holding tuples of the promoted canonical record types — account snapshots, owner observations and associations and allocations, appraisal and taxable value observations, taxing-unit and exemption observations, land and improvement observations, and geometry observations — with no generic mapping, no JSON payload, no free-form metadata attribute, and no database-shaped row type. Add `ReleaseLoadCompletion`, a frozen type carrying the `ProcessingRunRef` and `already_complete: bool`, and `MissingReleaseIdentifier`, an exception raised when a load is opened for a release whose identifier the source never established. State in the batch's docstring that it defines no key over observed values, so divergent evidence at one grain, several children of a one-to-many type, and several geometries all pass through unchanged.

<!-- countyforge-task: 3.2 paths=libs/property-tax-application/src/property_tax_application/canonical.py checks=repo.check risk=higher_risk prerequisites=D2,D3,D4,3.1 -->
- [ ] 3.2 Add the canonical load session and repository — In `canonical.py`, add `ReleaseLoadSession`, a Protocol with `__enter__`, `__exit__` annotated `-> None` so a failure cannot be suppressed, `write(batch)` accepting successive bounded batches with nothing durable until completion, `abort()` leaving zero canonical records, and `commit()` returning a `ReleaseLoadCompletion`. Add `CanonicalReleaseRepository`, a Protocol whose one method opens a session for a `ReleaseIdentity`, a `ProcessingRunRef`, and a `ReleaseProcessingOutcome`, raising `MissingReleaseIdentifier` where the identity is incomplete. Document on `commit` that the outcome and the load become durable together at that single point, and why: the database gate that requires an accepted outcome is `DEFERRABLE INITIALLY DEFERRED`, so an implementation splitting them across units of work cannot satisfy it. Document that re-completing an already-completed release and run returns `already_complete=True` and writes nothing further, and that a second distinct run for one release is a new load rather than a retry. Name no schema, table, cursor, connection, transaction, bulk-load mechanism, conflict clause, or surrogate key.

## 4. Quality and publication

<!-- countyforge-task: 4.1 paths=libs/property-tax-application/src/property_tax_application/quality.py checks=repo.check risk=normal prerequisites=D7,1.1 -->
- [ ] 4.1 Add the quality boundary — Add `quality.py` carrying `RuleSeverity` (exactly `blocking` and `warning`), `QualityRule` holding the rule identifier, version, severity, family, and its configured threshold, and `QualityEvaluation` holding the rule reference, `passed`, an optional subject, and the measured and expected values — validating that a failing evaluation carries both, which is what the accepted model requires. Add `QualityRepository`, a Protocol that reads the active configured rules and records evaluations against a `ProcessingRunRef`. Embed no county name and no threshold value. Define no second rule or evaluation model.

<!-- countyforge-task: 4.2 paths=libs/property-tax-application/src/property_tax_application/publication.py checks=repo.check risk=higher_risk prerequisites=D8,D9,1.1 -->
- [ ] 4.2 Add the publication boundary — Add `publication.py` carrying `PublicationProduct` (exactly `latest_available`, `latest_certified`, `history`), `PublicationRef` documented as an opaque locator on the same terms as `ProcessingRunRef`, and `PublicationSession`, a Protocol with `activate()` making the build current and superseding the previous publication, and `fail()` leaving the previously current publication current and marking the build failed. Add `PublicationRepository` opening a session for a product, a `ReleaseIdentity`, and a `ProcessingRunRef`. State in the module docstring that the boundary carries publication decisions and lineage only: it grants no canonical read privilege, and field-level publication permission remains governed by the reviewed field policy.
