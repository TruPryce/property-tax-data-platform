# Tasks

Field bounds are named rather than restated. Where a task says **identifier**, **label**,
**address component**, **amount**, **magnitude**, **percentage**, **instant**, or **year**, it means
the rule D8 fixes and the capability requires. Restating a bound here would be a second copy of it.

**Shared columns.** Where a task says a relation carries *the shared lineage columns*, it means
`snapshot_key`, `release_key`, `load_key`, and `provenance_key`, all `bigint NOT NULL`, with the two
composite foreign keys `(snapshot_key, release_key)` into `canonical.account_snapshot` and
`(provenance_key, release_key, load_key)` into `canonical.provenance`. The first makes a child's
release its parent's; the second makes the child's own load and release its provenance's. Parent and
child may have different loads and artifacts for the same release, as the accepted canonical contract
permits. No record relation carries a release identifier, tax year, release kind, or artifact of its
own.

**Shared migration frame.** Every migration in section 1 carries the same frame, which is not repeated
per task: the `file_sha256` guard that raises rather than `\quit`; a prerequisite check that the
**immediately preceding** migration is recorded in `platform.schema_migration`; an already-applied
check that raises `migration NNNN is already applied`; one `BEGIN`/`COMMIT` around the whole file;
`SET LOCAL lock_timeout` and `SET LOCAL statement_timeout`; grants for every object it creates; and
the ledger insert. No down migration is written for any of them. The task prerequisites below form the
same strict chain the guards do, so no migration can be scheduled before the file its own guard
requires.

**Execution lane.** These paths cannot be authored by the governed CountyForge implementation runner,
and that is measured rather than assumed: `infra/` is outside `allowed_write_roots` in
`.ai/policies/countyforge-implementation-paths.v1.json`, and `migrations/` matches the runner's
higher-risk path set, which refuses unconditionally. Task 3.4 is therefore direct-lane work, in the
same way the archival lane is — it cannot write under `openspec`. The authorized paths below are the
review contract, not a runner packet.

## 2. Falsification suites

Every suite in this section inspects a real PostgreSQL — catalogs, constraints, privileges, and
behaviour — rather than searching SQL source text, because a test that greps a migration passes for a
constraint that was written and never took effect. Each skips without a database, as
`tests/integration/postgres/test_migrations.py` already does, and each runs as the role
whose privileges it is judging rather than as the owner. Resolve every key by lookup rather than by
literal: a refused insert still consumes an identity value, so hard-coded keys drift and a later
assertion then passes for the wrong reason.
