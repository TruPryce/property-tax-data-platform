# Tasks

Field bounds are named rather than restated. Where a task says **identifier**, **label**,
**address component**, **amount**, **magnitude**, **percentage**, **instant**, or **year**, it means
the rule D8 fixes and the capability requires. Restating a bound here would be a second copy of it.

**Shared columns.** Where a task says a relation carries *the shared lineage columns*, it means
`snapshot_key`, `release_key`, `provenance_key`, and `load_key`, all `bigint NOT NULL`, with the three
composite foreign keys `(snapshot_key, release_key)` into `canonical.account_snapshot`,
`(provenance_key, release_key)` into `canonical.provenance`, and `(load_key, release_key)` into
`canonical.release_load`. The shared `release_key` column across those keys is what makes a child's
release equal to its parent's without a trigger.

**Shared migration frame.** Every migration in section 1 carries the same frame, which is not repeated
per task: the `file_sha256` guard that raises rather than `\quit`; a prerequisite check on
`platform.schema_migration`; an already-applied check that raises
`migration NNNN is already applied`; one `BEGIN`/`COMMIT` around the whole file; `SET LOCAL
lock_timeout` and `SET LOCAL statement_timeout`; grants for every object it creates; and the ledger
insert. No down migration is written for any of them.

**Execution lane.** These paths cannot be authored by the governed CountyForge implementation runner,
and that is measured rather than assumed: `infra/` is outside `allowed_write_roots` in
`.ai/policies/countyforge-implementation-paths.v1.json`, and `migrations/` matches the runner's
higher-risk path set, which refuses unconditionally. Task 3.4 is therefore direct-lane work, in the
same way the archival lane is — it cannot write under `openspec`. The authorized paths below are the
review contract, not a runner packet.

## 1. Forward migrations

- [ ] 1.1 Create the canonical schema and its lexical vocabulary — Add `infra/postgres/migrations/0006_canonical_schema.sql`. `CREATE SCHEMA canonical` with a comment distinguishing it from `silver`, which persists adapter-grain evidence. Define `canonical.is_identifier(text)` as `^[A-Za-z0-9_][A-Za-z0-9._-]{0,127}$`, `canonical.has_no_control_character(text)` as the explicit range `[\u0000-\u001F\u007F-\u009F]` rather than the locale-dependent POSIX class, `canonical.is_bounded_text(text, integer)` combining a length bound with `platform.is_named` and the control-character rule, and `canonical.is_finite(numeric)` as three inequalities against `NaN`, `Infinity`, and `-Infinity`, because `'NaN' = 'NaN'` is true in PostgreSQL and a single equality would admit it. Mark each `IMMUTABLE STRICT PARALLEL SAFE` and comment where the definition comes from. `GRANT USAGE ON SCHEMA canonical TO property_tax_ingestion` and `ALTER DEFAULT PRIVILEGES FOR ROLE property_tax_migrator IN SCHEMA canonical GRANT SELECT, INSERT ON TABLES TO property_tax_ingestion` — exactly those two privileges, so a later relation cannot inherit `UPDATE`. Grant `property_tax_api` nothing, including schema usage, and say why in a comment.

- [ ] 1.2 Persist canonical release identity and the artifact association — Add `infra/postgres/migrations/0007_canonical_release_identity.sql`. `canonical.release` carries `release_key bigint GENERATED ALWAYS AS IDENTITY PRIMARY KEY` commented as a persistence locator, `jurisdiction_code`, `tax_year`, `release_kind`, `release_identifier`, and `first_recorded_at`, all `NOT NULL`. - [ ] 1.3 Bind a canonical release to the run that loaded it, and gate it on acceptance — Add `infra/postgres/migrations/0008_canonical_release_load.sql`. `canonical.release_load` carries `load_key` as a locator, `release_key`, `run_id`, `jurisdiction_code`, `tax_year`, `release_kind`, `release_identifier`, and `loaded_at`, all `NOT NULL`. Add the two composite foreign keys **over the same four component columns** — one into `canonical.release (release_key, jurisdiction_code, tax_year, release_kind, release_identifier)` and one into `ingestion.run (run_id, jurisdiction_code, release_identifier, tax_year, release_kind)` — so the canonical release a run loads is the release that run processed, and a Collin run cannot register a Dallas release. Add `UNIQUE (release_key, run_id)` as the retry anchor and `UNIQUE (load_key, release_key)` as the record foreign-key target. Add a `DEFERRABLE INITIALLY DEFERRED` constraint trigger requiring, at `COMMIT`, that the named run has an `ingestion.release_outcome` with `disposition = 'accepted'`, mirroring the deferred seal `0003` already uses, so a rejected release leaves no canonical record. Derive nothing: no `release_identifier` is constructed from a filename, digest, tax year, kind, row order, or acquisition time, and a run whose components fall outside the canonical contract simply has no canonical release. Set the timeouts: this migration references `ingestion.run`, which may be live, and adding a foreign key takes `ShareRowExclusiveLock` on it.

## 2. Falsification suites

Every suite in this section inspects a real PostgreSQL — catalogs, constraints, privileges, and
behaviour — rather than searching SQL source text, because a test that greps a migration passes for a
constraint that was written and never took effect. Each skips without a database, as
`tests/integration/postgres/test_migrations.py` already does, and each runs as the role
whose privileges it is judging rather than as the owner.

- [ ] 2.1 Prove identity, grain, and evidence divergence — Add `tests/integration/postgres/test_canonical_identity.py`. Assert that two accounts with one `source_account_id` in two jurisdictions both persist and are distinct, and that `pg_index` holds no unique index covering `source_account_id` alone. Assert that two snapshots sharing `(account_key, release_key)` with different provenance both persist, that no unique index covers exactly those two columns, and that the grain index exists and is not unique. Assert the root invariant refuses an account of one county under another county's release. Assert each `*_key` column carries a comment naming it a persistence locator, and that every relation with a business identity also carries that identity as a `UNIQUE`.
